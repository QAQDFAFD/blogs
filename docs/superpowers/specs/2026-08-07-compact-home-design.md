# 紧凑文章流首页设计

## 目标

首页不再承担品牌落地页或精选文章展示职责。访问者进入博客后直接看到已发布文章；新增 Markdown 或 MDX 文章并构建后，文章自动进入首页列表。

## 页面结构

首页保留全站导航，删除以下内容：

- 大尺寸 Hero 文案与主题标签
- 精选文章卡片及装饰标签
- “最近写了什么”介绍区

导航下方直接进入文章区域：

1. 紧凑页头显示“文章”和已发布文章数量。
2. 已发布文章按日期倒序排列。
3. 文章数量达到 5 篇时显示搜索框；不足 5 篇时隐藏，避免空内容阶段出现多余控件。
4. 超过每页数量后沿用现有分页。

## 文章卡片

桌面端使用最大宽度 880px 的单列横向卡片：

- 左侧为 260px 宽的封面栏，图片覆盖卡片完整高度，使用 `object-fit: cover` 裁切。
- 右侧依次显示分类与阅读时间、标题、摘要、标签和发布日期。
- 整张卡片可点击，不再增加独立“阅读全文”大按钮，降低视觉重量。

移动端在 767px 以下切换为上下布局：

- 封面位于顶部并保持 16:9。
- 正文信息位于下方。
- 所有链接维持至少 44px 的可点击区域和可见焦点状态。

没有封面时，卡片直接使用完整宽度展示正文信息，不保留空白占位。

## 封面异常修复

当前图片元素带有 `width="1600" height="1000"` 尺寸提示，卡片 CSS 只覆盖了宽度，导致浏览器保留 1000px 的计算高度。桌面横向卡片的封面显式使用 `height: 100%` 覆盖 HTML 高度提示并填满网格栏；移动端切换为 `height: auto`、`aspect-ratio: 16 / 9`。两端均使用 `object-fit: cover`。

## 组件与数据流

- `src/pages/index.astro` 继续通过 `getPublishedPosts()` 获取并分页文章，只负责决定是否渲染搜索框与列表。
- `PostList.astro` 保持列表容器职责。
- `PostCard.astro` 保持文章数据到卡片内容的映射，不引入客户端状态。
- 搜索、归档、标签、RSS、文章页和评论系统不受本次调整影响。

## 响应式与验证

实现后验证以下内容：

- 自动化测试、Astro 类型检查、生产构建与产物校验全部通过。
- 增加针对卡片封面高度规则的回归测试，避免 HTML 高度提示再次覆盖卡片比例。
- 在 375、768、1024、1440px 下检查无横向溢出。
- 在 1273×963 下确认文章封面不再计算为 1000px 高。
- 线上首页首屏直接出现文章列表，文章页和 Giscus 配置保持正常。
