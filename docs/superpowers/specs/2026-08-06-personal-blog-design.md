# JiaJun Li 个人博客设计说明

## 目标

将当前仓库改造成一个基于 Astro 的个人技术博客。作者通过提交 Markdown 或 MDX 文章完成日常发布，推送到 `main` 后由 GitHub Actions 自动构建并部署到 GitHub Pages。博客使用 GitHub Discussions 和 Giscus 提供评论，不引入 VitePress 式文档站能力。

默认生产地址为 `https://qaqdfafd.github.io/blogs/`，所有站内链接、静态资源、RSS 和站点地图必须兼容 `/blogs/` 路径前缀。

## 设计定位

这是面向开发者读者的个人编辑型博客，作者署名为 `JiaJun Li`。视觉方向为紧凑的 Editorial Ledger，参考 `https://langqi99.com/blog/` 的文章信息组织与宽幅卡片结构，但不复制其终端窗口、交通灯装饰和大量胶囊标签。

设计参数：

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 3`
- `VISUAL_DENSITY: 5`

页面使用原生 CSS 和 Astro 组件实现，不引入通用 UI 设计系统。动效只承担交互反馈，不加入滚动劫持、持续动画或装饰性视差。

## 信息架构

站点包含以下公开页面：

- 首页：作者介绍、文章筛选入口和按日期倒序排列的文章卡片。
- 文章页：标题、摘要、发布日期、阅读时长、标签、正文目录、正文、上一篇/下一篇和评论。
- 归档页：按年份和月份组织全部已发布文章。
- 标签页：展示全部标签及数量，并支持进入单个标签的文章列表。
- 关于页：展示作者介绍与 GitHub 链接。
- RSS：输出全部已发布文章。
- 站点地图：输出所有公开页面和文章地址。
- 404 页面：提供返回首页和查看文章的入口。

导航在桌面端保持单行，包含文章、归档、标签、关于、GitHub 和主题切换。移动端保留站点名、文章入口和一个菜单按钮，其余入口进入展开菜单。

## 内容模型

文章存放在 `src/content/blog/`，由 Astro Content Collections 校验。每篇文章支持 Markdown 或 MDX，字段定义如下：

- `title: string`，必填。
- `description: string`，必填，用于列表摘要、SEO 和分享卡片。
- `pubDate: date`，必填。
- `updatedDate: date`，可选。
- `tags: string[]`，默认空数组。
- `category: string`，默认 `随笔`。
- `cover: image | string`，可选，可使用本地图片或远程图片。
- `coverAlt: string`，存在封面时必填。
- `draft: boolean`，默认 `false`。

阅读时长在构建阶段根据正文内容自动计算。列表、RSS、站点地图和上一篇/下一篇都排除草稿。文章 slug 由文件名生成，迁移现有文章时使用稳定的英文 slug `webpack-loader-plugin`。

现有 `docs/webpack 的 loader 和 plugin 原理解析.md` 会迁移为第一篇内容文章，正文内容和现有图片链接保持不变，只增加通过 schema 校验所需的元信息。

## 首页布局

桌面端使用约 960px 的居中内容容器。顶部导航高度不超过 64px。作者标题区为左对齐布局，标题为“把复杂的技术，写得更清楚。”，说明为“前端工程、构建工具与软件设计。”。归档、标签和搜索入口位于标题区附近，不占用独立大区块。

文章列表为单列紧凑卡片：

- 实际卡片宽度约 908px。
- 卡片统一使用 12px 圆角和轻微的背景同色阴影。
- 有封面时，文字在左、封面在右，封面占卡片宽度约 29%。
- 没有封面时，文字内容扩展到完整卡片宽度，不保留空白图片区。
- 卡片高度由内容决定，典型范围为 168px 到 184px，不强制所有卡片等高。
- 元信息包含文章路径、真实阅读时长、分类、标签和发布日期。
- 不展示无法从正文可靠计算的虚构字数或其他装饰数字。
- 整张卡片可点击，同时保留语义正确的文章链接和清晰键盘焦点。

移动端在小于 768px 时改为单栏：封面位于文字上方，工具入口横向滚动或折叠，卡片间距收紧，页面左右内边距为 16px。

## 文章页布局

文章页延续同一主题和颜色系统。标题区显示分类、阅读时长、标题、摘要、发布日期与作者。正文宽度控制在约 65 个字符，代码块允许横向滚动。

桌面端正文右侧提供粘性目录：

- 目录由 Markdown 的二级和三级标题自动生成。
- 阅读过程中高亮当前章节。
- 点击目录使用原生锚点平滑定位。
- 关闭 JavaScript 时目录链接仍然可用。

移动端目录移动到正文之前，默认折叠为“本文目录”，展开后显示完整层级。文章末尾依次显示上一篇/下一篇和评论区。

## 视觉系统

视觉使用冷中性的浅灰纸张色和近黑文字，唯一强调色为低饱和森林绿。深色主题使用同一套层级关系，不在页面中途切换主题色系。禁止纯黑、纯白、紫色光晕和渐变大标题。

字体采用自托管的现代无衬线字体与等宽字体组合，优先考虑 Geist Sans 和 Geist Mono，并设置 `font-display: swap`。中文正文使用系统中文字体回退，保证加载速度和字形完整性。

形状规则：

- 内容卡片为 12px 圆角。
- 小型按钮、筛选控件和输入框为 8px 圆角。
- 标签默认用文字与间距区分，不把所有标签做成胶囊。

交互规则：

- 卡片悬停仅改变边框、阴影和最多 2px 的垂直位移。
- 按钮按下使用 1px 位移或轻微缩放反馈。
- 页面载入可使用短暂的透明度过渡。
- 所有过渡在 `prefers-reduced-motion: reduce` 下关闭。
- 所有文本、按钮、输入框、焦点环和评论状态满足 WCAG AA 对比度。

## 图片策略

首页至少呈现两张真实或生成的编辑型图片，包括首篇文章封面和一张支持性文章封面。现有文章正文中的远程图片继续保留。新文章封面是可选字段，缺少封面时使用纯文字卡片，不生成空白占位图，也不使用手写 SVG 或由 div 拼出的假截图。

图片必须声明尺寸或宽高比，避免布局偏移。首屏图片按需要预加载，其余图片懒加载。所有内容图片必须有替代文字。

## 搜索、筛选和分页

初始版本提供构建时生成的轻量客户端搜索索引，搜索范围为标题、摘要、分类和标签。搜索输入具有可见标签、清空按钮、空结果提示和键盘焦点状态。

归档和标签为独立静态页面。首页文章数量超过 10 篇时启用分页，每页 10 篇；不足 10 篇时不显示分页控件。分页生成静态路由并保持可抓取链接。

## GitHub Discussions 评论

评论使用 Giscus，目标仓库为 `QAQDFAFD/blogs`。每篇文章按 `pathname` 映射到一个 Discussion，避免标题修改导致评论丢失。评论主题随站点明暗主题同步。

首次部署需要仓库所有者完成以下一次性操作：

1. 为仓库启用 GitHub Discussions。
2. 安装并授权 Giscus GitHub App 访问该仓库。
3. 选择允许 Giscus 使用的 Discussions 分类。
4. 将仓库 ID 和分类 ID 写入公开构建配置。

仓库 ID 和分类 ID 是公开标识，不作为密钥处理。配置缺失时文章仍正常渲染，评论区显示可操作的配置提示；脚本加载失败时显示“评论暂时无法加载”和重试入口。加载期间使用与最终评论区域近似的骨架占位，减少布局偏移。

## 主题与客户端行为

主题默认跟随 `prefers-color-scheme`。用户手动选择后保存到 `localStorage`，页面在首次绘制前应用已保存主题，避免闪烁。所有核心内容和导航在 JavaScript 关闭时仍可访问，只有主题记忆、当前目录高亮、搜索和 Giscus 属于增强行为。

## 部署

Astro 配置使用：

- `site: https://qaqdfafd.github.io`
- `base: /blogs`
- 静态输出模式。

GitHub Actions 在推送到 `main` 后执行依赖安装、类型检查、构建和 GitHub Pages 部署。工作流使用官方 Pages Actions，并为并发部署启用取消旧任务。构建失败时不覆盖当前线上版本。

README 记录本地命令、写作格式、发布流程、GitHub Pages 设置、Discussions 设置和 Giscus 配置。完成一次性设置后，日常发布流程仅为新增或修改文章并推送到 `main`。

## 异常与空状态

- 没有已发布文章：首页显示“还没有发布文章”，并保留关于页与 RSS 入口。
- 搜索无结果：显示当前查询及清空搜索入口。
- 封面加载失败：隐藏破损图片并让文字区域占满卡片。
- Giscus 未配置：显示 README 中对应配置章节的链接。
- Giscus 加载失败：显示简洁错误提示和重试按钮。
- 文章路由不存在：展示自定义 404 页面。
- 外部正文图片失败：保留替代文字和稳定尺寸，不影响正文继续阅读。

## SEO 与可访问性

每个页面提供唯一标题、描述、canonical URL、Open Graph 元数据和适当的语言声明。文章页输出 BlogPosting JSON-LD，并使用真实发布日期和更新时间。RSS、站点地图和 canonical URL 都包含 `/blogs/` 前缀。

页面使用语义化的 `header`、`nav`、`main`、`article`、`aside` 和 `footer`。提供跳过导航链接、可见焦点、键盘可操作菜单和主题切换、正确的标题层级及足够的点击目标。目录当前项高亮不只依赖颜色。

## 验证策略

自动验证包括：

- 内容 schema 对合法和非法 frontmatter 的校验。
- 草稿过滤、日期排序、阅读时长和分页逻辑测试。
- URL 与 `/blogs/` 前缀生成测试。
- `astro check` 类型检查。
- 生产构建和生成文件检查。
- 内部链接、RSS、站点地图与 canonical URL 检查。

浏览器验证覆盖：

- 首页、文章页、归档页、标签页、关于页与 404 页。
- 375px、768px 和桌面视口。
- 浅色与深色主题。
- 键盘导航、菜单、主题切换、搜索和折叠目录。
- Giscus 已配置、加载中、失败和未配置状态。
- `prefers-reduced-motion` 下无非必要动画。
- Lighthouse 的可访问性、SEO、最佳实践和性能检查，目标为 LCP 小于 2.5 秒、INP 小于 200 毫秒、CLS 小于 0.1。

## 不在范围内

- 文档版本、多层文档导航、全文文档侧边栏。
- CMS、管理后台或在线 Markdown 编辑器。
- 用户注册、私有文章或站内账号体系。
- 点赞、访问量、订阅邮件和复杂分析系统。
- 服务端数据库或运行时 API。
