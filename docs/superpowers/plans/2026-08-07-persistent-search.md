# Persistent Compact Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep homepage search permanently visible without restoring the visual weight removed from the compact article feed.

**Architecture:** Reuse the existing `SearchBox.astro` index loading and filtering behavior. Change only the homepage render condition, compact the existing CSS container, and make the production verifier require the search control and base-aware index URL.

**Tech Stack:** Astro 7, TypeScript 6, Vitest 4, static JSON search index

## Global Constraints

- Search always appears between `.home-list-header` and `.post-list`.
- Search continues to fetch `/blogs/search-index.json` through `withBase()`.
- Desktop and mobile controls stay on one line.
- The clear button remains at least 44×44px.
- Empty search status and results add no vertical space.
- Article cards, pagination, archive, tags, RSS, article pages, and Giscus remain unchanged.

### Task 1: Make the built-output contract require search

**Files:**
- Modify: `scripts/verify-build.mjs`
- Test: `scripts/verify-build.mjs`

**Interfaces:**
- Consumes: `dist/index.html` generated by `npm run build`.
- Produces: an error when the homepage lacks `data-search` or `/blogs/search-index.json`.

- [ ] **Step 1: Write the failing verification rule**

Remove `data-search` from the removed-content list and add:

```js
for (const fragment of ['data-search', '/blogs/search-index.json']) {
  if (!home.includes(fragment)) throw new Error(`Homepage search missing: ${fragment}`);
}
```

- [ ] **Step 2: Run verification and confirm failure**

Run: `npm run build && npm run verify`

Expected: FAIL with `Homepage search missing: data-search`.
